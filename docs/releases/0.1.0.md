Universe 0.1.0 is a linux-64-only pre-release packaging checkpoint, not the integrated v1 release.

`decision-132` defines this tag: three real `linux-64` Conda packages, a rendered publish
workflow with three declared destinations, and a rendered restore entrypoint. The main-CLI
amendment brings `universe-kit` and the umbrella `universe` facade into the checkpoint.
`decision-119` still defines the stable v1 release; this tag does not supersede it.

## What this tag contains

- Three `linux-64` Conda packages: `universe-airlock`, `universe-kit`, and the umbrella
  `universe` facade. The workflow that publishes them to prefix.dev, to a static channel on a
  Git branch, and as GitHub Release assets is rendered from `universe.toml` and drift-checked
  in CI.
- A rendered restore entrypoint (`.universe-airlock/restore.sh`) that clones a pinned ref,
  checks the commit after the checkout, and hands over to the bootstrapper in that ref.
- Three verbs are real at this tag. `version` and `verify` belong to the installed
  `universe-airlock` binary; the latter checks a closed payload without activating anything.
  `restore` belongs to the separately built `universe-airlock-bootstrap` binary, which
  materialises that payload into an immutable environment and swaps one `current` link.

The repository's tests prove that a branch channel carrying a Conda dependency edge resolves
offline with Pixi when network access is denied. That is a property of the test channel, not of
every published branch: run `43045274207` left `refs/heads/channel` holding only one of the
three packages. Run `43061441347` re-watched with the corrected renderer; its one branch
snapshot carries all three packages, and a fresh prefix.dev read-back resolves all three by
digest. The offline solve of that published branch with network denied is still unrecorded, so
the destination criterion in `UNI-59` stays open. The clean-container restore transcript is
evidence recorded at the tag, not a claim made here.

## Not a v1 release

`decision-119` requires six surfaces for a stable v1. This tag completes none of them:

| v1 surface | State at 0.1.0 |
| :-- | :-- |
| Conda packages and a standards-compliant static Conda channel | three packages, one platform |
| Cargo sparse index and crate archives | absent |
| Python wheels and a Python-compatible package index | absent |
| npm packages through an npm-compatible registry surface | absent |
| Airlock consumption across the supported ecosystems | one consumer package, one platform |
| A browsable static portal generated from a pinned catalog | absent |

Also out of scope: every platform beyond `linux-64` (`decision-132`); a signed sealed
payload (`UNI-55`); and a
Pixi-managed environment (`UNI-51`). The bootstrap accepts an unsigned payload in the
`developer` lane and refuses the `sealed` lane until a trusted release key is compiled in.

## How this is checked

`pixi run gates` runs the whole suite. `pixi run repo-check` compares the workspace version,
the component recipes, the first versioned section of `CHANGELOG.md`, the newest `v*`
tag, and this file. When a `v0.1.0` tag exists, the check also compares its annotation
subject with the first line above, so criterion 2 cannot annotate the tag differently.
