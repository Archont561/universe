# Universe Kit CLI and manifest specification

## Status

Approved domain specification for consumer repository manifests (`universe.toml`, `package.toml`), CLI subcommands, DAG planning, external native-command orchestration, pure-Rust `goblin` binary auditing, upstream release watching, and generated consumer workflows (`decision-1`, `decision-3`, `decision-5`, `decision-8`).

**Scope amendment (decision-119):** the integrated v1 includes Conda, Cargo crates, Python wheels, npm packages, Airlock consumption, a browsable portal, and a standard static Conda channel. Kit may invoke a configured native build/test command and validate/collect its outputs, but it does not implement or bundle package builders. This document's older Conda-centric manifest/command examples are the initial interface contract; the versioned multi-ecosystem manifest and release-asset schema are tracked by UNI-41. Public command invocation uses the thin `universe` facade described in doc-111; direct component executables remain available.

## Consumer repository layout

A universe repository managed by `universe-kit` contains zero Python or shell CI glue:

```text
my-universe-kit/
├── universe.toml                     # Universe policy, platforms, channels, [[targets]], [pages]
├── pixi.toml                         # Pins universe-kit from archont561/archont561 (conda-forge first)
├── variant_config.yaml               # Optional shared rattler-build variants
├── recipes/
│   └── <pkg>/
│       ├── recipe.yaml               # Standard rattler-build v1 recipe (multi-output staging supported)
│       ├── package.toml              # Upstream watch source, binary audit overrides, smoke-test docs
│       └── patches/                  # Optional source patches
└── .github/workflows/
    ├── universe.yml                  # @generated — plan/validate/build/audit/verify, contents: read
    ├── release.yml                   # @generated, only when [[stores]] exist — tag-gated fan-out
    ├── universe-airlock.yml          # @generated, only when lock adapters exist — mirror lanes
    └── universe-watch.yml            # @generated, only when [upstream] exists — scheduled polling
```

Generated workflow files are split by **trigger family**, not by target or ecosystem
(`decision-124`). The set is derived from the manifest: a consumer repository gets one file,
a producer gains `release.yml` when it declares stores, and the airlock and watch
files appear only when their inputs do. Every file carries the
`# @generated by universe-kit <ver> — sha256:<digest>` header, and `universe ci check`
verifies each of them against the same manifest.

Repository housekeeping workflows are never generated: a workflow that commits cannot be
digest-verified.

**Status note — reversal.** The tag-triggered file in the tree above was
`universe-publish.yml`. It is now `release.yml`, the workflow filename the channel's trusted
publisher was registered with; GitHub puts that basename in `workflow_ref`, so a name the
publisher does not know cannot mint a token. `decision-124` records the reversal. `ci render`
removes the former file, and `ci check` refuses it if it reappears.

## Manifest contracts

### 1. `universe.toml` (`schemas/universe.schema.json`)

- **Strict unknown-key rejection**: `#[serde(deny_unknown_fields)]` refuses typos with dotted-path diagnostics.
- **`schema = 1`**: Required version discriminator.
- **`[universe]`**:
  - `name` (required non-empty slug), `description`, `repository` (HTTPS URL), `platforms` (subset of `["linux-64", "linux-aarch64", "win-64", "osx-64", "osx-arm64", "noarch"]`, non-empty).
- **`[build]`**:
  - `channels` (default `["conda-forge"]`, resolved in order during `plan`, `build`, and `test`).
  - `skip_existing` (`"all" | "local" | "none"`, default `"all"`).
  - `variant_config` (optional relative path, e.g., `"variant_config.yaml"`).
- **`[audit]`**:
  - `enforce_license_file = true`
  - `require_valid_spdx = true`
  - `forbid_build_path_leak = true`
  - `verify_arch_headers = true`
- **`[[targets]]`** (`#[serde(tag = "kind", rename_all = "kebab-case")]` — zero hardcoded `archont561` defaults):
  - **Shape note.** `[[targets]]` merges "what is built" with "where it goes", which cannot express one build publishing to two destinations. `decision-127` proposes splitting it into `[[packages]]` and `[[stores]]`, adding a catalog facet, and declaring store capabilities (`writable`, `needs_index`, `read_auth`, `verifier`) so the renderer never special-cases an ecosystem. That record is `proposed`; until it is accepted, the kinds below remain authoritative.
  - `kind = "prefix-dev"`: `{ channel: String, url?: Url, auth: "oidc" | "token", generate_attestation?: bool }`
  - `kind = "github-pages"`: `{ release_tag_prefix?: String /* default "packages" */, base_url?: Url, index_branch?: String /* default "universe-index" */, max_builds_per_version?: usize }`
  - `kind = "anaconda"`: `{ owner: String, label?: String }`
  - `kind = "s3"`: `{ bucket: String, region: String, endpoint_url?: Url, prefix?: String, force_path_style?: bool }`
  - `kind = "quetz"`: `{ url: Url, channel: String }`
  - `kind = "artifactory"`: `{ url: Url, channel: String }`
  - `kind = "filesystem"`: `{ path: PathBuf }`
- **`[airlock.developer]`** (`decision-104`):
  - `adapters` (`"pixi" | "bun" | "cargo"`, each once), `mirror?` (branch prefix the mirror lane writes).
  - `[airlock.developer.restore]` — the ref a disconnected host fetches, declared rather than looked up:
    `remote` (URL or path), `branch`, `commit` (full lowercase 40-hex, **not** a branch head),
    `bootstrap?` (default `universe-airlock-bootstrap`), `dir?` (default `.universe-airlock`, the
    directory both scripts are written into; must be relative and stay inside the project —
    `manifest.airlock.restore.dir`). `dir` belongs in the manifest because the files are committed
    and drift-checked: a check whose location came only from a flag nobody passed would compare
    the wrong file and report agreement. Every value is held to the charset a single-quoted shell
    string survives — letters, digits, `. - _ ~ : / @ +` — because the renderer interpolates without
    escaping (`manifest.airlock.restore.unsafe`); a commit that is not a full id is refused
    (`manifest.airlock.restore.commit`). Declaring adapters without a restore scope is a warning
    (`manifest.airlock.restore.missing`), since a mirror lane can land before anything is published
    to restore from.
- **`[pages]`**:
  - `enabled: bool`
  - `title: String`
  - `tagline?: String`
  - `accent_color?: String` (validated CSS hex `#RRGGBB`)
  - `channel_alias?: Url` (optional primary channel URL displayed first in install tabs)

### 2. `recipes/<pkg>/package.toml` (`schemas/package.schema.json`)

- **`schema = 1`** (`#[serde(deny_unknown_fields)]`).
- **`[upstream]`** (optional):
  - `provider = "github-releases" | "github-tags" | "pypi" | "crates-io" | "git"`
  - `repo` / `package` / `url`
  - `include_prereleases = false`
  - `tag_prefix = "v"` / `version_regex` (optional regex with `(?P<version>...)` capture)
  - `mode = "pr" | "issue"` (whether `watch` opens an automated version-bump PR updating `context.version` + `sha256` or files a deduplicated tracking issue).
- **`[platforms]`** (optional):
  - `only` / `skip` per-recipe platform filter intersecting `universe.platforms`.
- **`[audit]`** (optional):
  - `expected_binaries = ["bin/CloudCompare"]` (relative prefix paths that MUST exist and match target architecture).
  - `allowed_system_libs = []` (explicit allowlist additions beyond standard OS/loader libs).
  - `ignore_rpath_globs = []` (explicit opt-out globs with mandatory `reason` field).
- **`[docs]`** (optional):
  - `featured = false`
  - `category?: String`
  - `evidence_markdown?: PathBuf` (relative Markdown file rendered via `pulldown-cmark` + sanitized for the portal's "Verification Evidence" panel).

## CLI command grammar (`universe-kit`)

Derived via `clap` with `--json` structured output support on inspection/CI verbs:

1. **`universe init [--dir <path>] [--name <slug>] [--store <spec>...] [--pages] [--with-skill]`**
   - Scaffolds `universe.toml`, `pixi.toml` (pinning `universe-kit` from `https://prefix.dev/archont561/archont561` with `conda-forge` first), `.gitignore`, `recipes/.gitkeep`, and the generated workflow files that the manifest's declared capabilities call for — between one and four of them (`decision-124`). Each carries a `# @generated by universe-kit <ver> — sha256:<digest>` header.
   - Derives the repository identity from the git remote and refuses to overwrite an existing manifest without `--force`. Prints the detected edition (owner or consumer) and the file set it rendered, so the mapping is never implicit.
   - `--with-skill` writes `.agents/skills/universe-kit/` from embedded `universe-assets`.
   - Re-rendering is `universe ci render`, not a flag on `init`: a discoverable verb beats an option buried on another command.

2. **`universe-kit add <name> [--from-github <owner/repo> | --from-pypi <pkg> | --from-crates <crate>]`**
   - Fetches latest upstream release tarball/tag, computes `sha256`, detects license SPDX + license files, and scaffolds `recipes/<name>/recipe.yaml` + `recipes/<name>/package.toml`.

3. **`universe-kit lint [--recipes-dir recipes] [--check-workflows] [--json]`**
   - Static rules ported and generalized from `CloudCompare-conda/scripts/lint.py`:
     - Valid `universe.toml` and `package.toml` against strict schemas.
     - Valid `recipe.yaml` v1 syntax with line/column spans (`marked-yaml`).
     - Every URL `source` carries a 64-hex `sha256`; every `git` `source` pins an immutable commit `rev` (branches/tags without `rev` are refused unless `--allow-mutable-git` is explicitly configured).
     - `about.license` parses as a valid SPDX expression (`spdx::Expression::parse`) and `about.license_file` is declared when `audit.enforce_license_file = true`.
     - `build.number` is a non-negative integer; `context.version` is well-formed (`rattler_conda_types::Version`).
     - Generated workflow digests match `universe.toml` when invoked as `universe ci check`. `universe ci check` and `universe ci render` own that responsibility (`decision-124`); `lint` keeps the manifest, recipe, license, and store-declaration rules.

4. **`universe-kit plan [--changed-only | --changed-or-missing] [--base-ref <git-ref>] [--platform <subdir>] [--json]`**
   - Renders each `recipes/*/recipe.yaml` per target platform via `rattler-build build --render-only --output-format json`.
   - Constructs a `petgraph::Graph` linking intra-universe outputs to downstream `host`/`run` consumers, rejecting cycles with a readable cycle trace.
   - Queries configured remote channels (`rattler_repodata_gateway`) when `--changed-or-missing` is active to skip `(name, version, build_string, subdir)` tuples already published across all configured targets.
   - Emits leveled GitHub Actions build matrix JSON (`levels: [{ level: 0, jobs: [...] }, ...]`) so intra-universe dependencies build in topological order.

5. **`universe-kit build --recipe <name|path> --target-platform <subdir> [--output-dir output] [--rattler-build-bin <path>]`**
   - On `win-*`: discovers Visual Studio / MSVC Build Tools natively in-process via `cc::windows_registry::find_tool` when `VCINSTALLDIR` is unset, injecting environment variables into the child `rattler-build` process (eliminating external PowerShell/`vswhere` setup steps).
   - Executes `rattler-build build` with universe channels, variant configs, `--skip-existing`, and `--no-test` (decoupling build from isolated test + audit stages).

6. **`universe-kit test --package-file <path.conda> [--rattler-build-bin <path>]`**
   - Runs `rattler-build test --package-file <path.conda>` in a clean isolated environment and records structured test pass/duration metadata for downstream fragment generation.

7. **`universe-kit audit <path.conda>... [--emit-fragment <dir>] [--json]`**
   - Streams `.conda` (`info-*.tar.zst` and `pkg-*.tar.zst`) in memory/temp-stream via `rattler_package_streaming` without external `tar`/`zstd` binaries:
     - **Metadata & License verification**: validates `info/index.json`, `info/about.json`, `info/paths.json` (`sha256` + `size_in_bytes` per path), `spdx` license validity, and non-empty bundled `info/licenses/*` files.
     - **Build-root path leak scan**: checks text prefix placeholders and binary string tables (`goblin`) to ensure host build roots (`$SRC_DIR`, `$BUILD_PREFIX`, runner workspace paths) never leaked un-relocated into shipped binaries/configs.
     - **Native binary header & RPATH inspection (`goblin`)**:
       - `linux-64` / `linux-aarch64`: verifies ELF64 (`EM_X86_64` / `EM_AARCH64`), inspects `DT_RUNPATH`/`DT_RPATH` (`$ORIGIN` relative paths permitted; absolute build paths forbidden), and records `DT_NEEDED` libraries.
       - `win-64`: verifies PE32+ (`IMAGE_FILE_MACHINE_AMD64`) across `.exe`/`.dll`/`.pyd` and records imported DLLs (flagging debug CRT `msvcp140d.dll`/`vcruntime140d.dll` leaks).
       - `osx-64` / `osx-arm64`: verifies Mach-O 64-bit (`CPU_TYPE_X86_64` / `CPU_TYPE_ARM64`), inspects `LC_RPATH` and `LC_LOAD_DYLIB` (`@rpath/`, `@loader_path/`, `/usr/lib/`, `/System/Library/` permitted; `/Users/runner/` or build-dir paths forbidden).
       - `noarch`: refuses compiled native ELF/PE/Mach-O binaries inside `noarch` packages.
     - **Expected binaries check**: verifies every path listed in `package.toml` `audit.expected_binaries` exists and is executable/loadable.
   - When `--emit-fragment <dir>` is set, writes deterministic `<dir>/<subdir>/<filename>.conda.json` (~1 KB) consumed by `pages build`.

8. **`universe-kit publish-artifacts <dir> [--target <kind|index>] [--dry-run]`**
   - Uploads `.conda` packages to every target in `universe.toml`:
     - `prefix.dev` / `anaconda.org` / `s3://` / `quetz` / `artifactory` via `rattler_upload` (supporting OIDC token exchange + `--generate-attestation` on `prefix.dev`).
     - `github-pages` target: ensures rolling GitHub Release `<prefix>-<subdir>` exists (`reqwest` GitHub REST v3 client), uploads `.conda` assets idempotently, applies optional `max_builds_per_version` retention pruning, and commits `.conda.json` fragments to `index_branch` (`universe-index`).
   - **Implemented (2026-11-04).** The verb is `universe publish-artifacts [--fragments <dir>] [--package <name>]... [--store <name>] [--force] [--dry-run] [--json]`. It proves every fragment against the bytes it names, then uploads `<subdir>/<file>` to each writable `[[stores]]` entry whose kind this verb writes: `prefix-dev`, `anaconda`, `s3`, `quetz`, `artifactory`, `filesystem`, and `releases` as one rolling release per subdir. `--store` names one of them; a `branch`/`static` store is refused here because `universe publish` is what pushes a tree. `auth = "token"` reads the environment variable named by the store's first `secrets` entry — the rendered name (`<STORE>_<SECRET>`) first, then the bare one. `auth = "oidc"` (implemented 2026-11-06) mints instead of reading: the job's CI identity (`GET $ACTIONS_ID_TOKEN_REQUEST_URL&audience=…`) is exchanged at `POST <server>/api/oidc/mint_token` for a short-lived bearer, once per server per run. The audience is `prefix.dev` for `prefix.dev` and its subdomains and the endpoint's host otherwise. It is defined only for a `prefix-dev` store: `auth = "oidc"` on any other kind is a manifest error (`manifest.store.oidc.unsupported`), and naming a secret alongside it is a warning (`manifest.store.oidc.secret`) because trusted publishing needs none. Two `[[stores]]` fields belong to a release store: `tag_prefix` (default `packages`, so a tag reads `<prefix>-<subdir>`) and `max_builds_per_version` (how many builds of one `(package, version)` survive the 1,000-asset cap). **Idempotency is digest-based**: an artifact whose `sha256` the destination already reports is skipped, and a different `sha256` under an occupied name is refused unless `--force` is given. **The rendered `v0.1.0` publish lane opts into that exception**: `ci render` adds `--force` to `publish-artifacts` for `prefix-dev` and `releases` stores, while `publish` for a branch or static store never carries it. prefix.dev requires a read-write-delete Repository Access entry to honour `?force=true`; attempt 1 of run `42920755513` received `403 Not authorized`, and attempt 2 is green after the owner removed the occupied variant manually. Run `43045274207` is green for all three packages after the variants were cleared again, with a fresh prefix.dev repodata read resolving all three by digest. Neither run proves force-replace permission. `decision-132` records the scoped reversal; the CLI default is unchanged and the build is still not reproducible. **Correction (2026-11-11):** that green run rendered three `publish --store branch` steps and left `channel` holding only the last package, because each `publish` replaces the whole orphan tree. `ci render` now emits one `publish` command naming every package for a branch or static store, while artifact stores keep one upload step per package; a Rust unit test, a BDD scenario and a Python scope test were red before the renderer changed. **`--dry-run` issues no mutating request** — reads build the plan, `PUT`/`POST`/`DELETE` are withheld. `https://` endpoints are spoken to over `rustls` (`aws-lc-rs`), per `decision-3`; an endpoint with no scheme at all is refused at construction, before any destination has been written. The rendered publish workflow calls this verb for every store it writes to and `universe publish` for a branch, which is the split the renderer enforces rather than a convention. A branch or directory tree also carries each artifact's audit receipt at `meta/<subdir>/<filename>.conda.json`, copied verbatim from what `universe audit --emit-fragment` wrote (`decision-5`, amended 2026-11-06: a branch store serves them from its single snapshot tree instead of a second index branch). A channel built this way is proved installable, not merely well-formed: `crates/universe-kit/tests/channel_resolves.rs` publishes, clones the branch, and resolves the package with `pixi install --offline`. Still unimplemented from the description above: the atomic `.conda.json` fragment commit to `index_branch`, and prefix.dev attestation. `universe publish` authenticates a branch push from the store's declared secret — supplied to git as `http.<origin>/.extraheader` through `GIT_CONFIG_*` environment variables, never argv — and falls back to git's own credential when the variable is unset, which is what a local run expects. **Its shape since 2026-11-08:** the verb is written against the `Transport` seam rather than against Git — `current`, `staged_tree`, `push` — so `--check` and the publish path are both testable with a fake, and `git.rs` runs every command through a `GitRunner` seam whose recorder asserts the exact argv a publish issues (one `init`, one `commit-tree` with no parent, one forced push). Staging happens in a temporary directory outside the payload and is removed when the run ends; `--output` names one explicitly and is refused if it sits where the artifacts are (`publish.scratch.inside-payload`). A symlink anywhere in the payload is refused before anything is read through it (`channel.payload.symlink`). Retention is `--keep <n>`, or the store's `max_builds_per_version` — the nearest `n` builds of each `(package, version)` survive, a build that a surviving fragment pins exactly (`name ==version=build`, or the older `name version build`) is refused rather than pruned (`publish.retention.pinned`), and the report states that a force-push bounds what the branch *serves* rather than what the repository stores (`retention.reclaims_storage: false` in JSON). A retained channel is proved installable: `crates/universe-kit/tests/channel_resolves.rs` publishes two builds with `--keep 1`, clones the branch, and resolves it with `pixi install --offline`.

9. **`universe-kit pages build --fragments <dir> --output <site-dir>`**
   - Synthesizes CEP-15 `repodata.json(.zst)`, CEP-16 `repodata_shards.msgpack.zst` + `shards/`, `run_exports.json(.zst)`, `channeldata.json`, `.nojekyll`, `catalog.json`, `packages/<name>/package.json`, and hydrated SvelteKit + UnoCSS static HTML pages (`doc-3`).
   - Conda solver/channel artifacts and portal/catalog generation are separate implementation layers (`UNI-12` and `UNI-25`/`UNI-46`) but both are required for integrated v1. Conda metadata and binaries must remain available at standard static channel paths; portal HTML is not the registry.

10. **`universe airlock render [--check] [--output <dir>] [--root <dir>] [--stdout] [--json]`** (`UNI-53`, `decision-104`)
    - Writes the committed restore entrypoints from the manifest: `<dir>/restore.sh` (mode 755) and `<dir>/restore.ps1` — `dir` from `[airlock.developer.restore]`, default `.universe-airlock` — plus the `<!-- airlock:begin -->` block of `README.md`, which stays at the root. `--output <dir>` overrides the directory for one invocation (a scratch render, a preview); when it differs from the manifest's `dir` the render says so on stderr, because the committed file is then unchanged while `airlock-check` still compares it. A project that declares no `[airlock.developer.restore]` renders nothing, and any generated entrypoint left behind by a scope that went away is named (`airlock.render.stale`) — removed by `render`, failed by `--check`.
    - The entrypoint clones `remote` at `branch`, checks out `commit`, verifies the checkout really is that commit, and executes `bootstrap restore --commit <pinned>`; a rewritten ref and a ref published without a bootstrapper both fail with a message rather than running something else. `UNIVERSE_AIRLOCK_HOME` chooses where the checkout is cached (`$XDG_CACHE_HOME/universe-airlock` by default), so a second run is a reuse rather than a clone.
    - **No runtime digest is embedded.** The pin is the commit; the digest of what it fetches lives in the ref. That keeps the generated bytes stable across releases of this tool, which is what makes the drift check meaningful: rendering is a pure function of the manifest, two renders are byte-identical, and `--check` exits `1` with a line diff when the committed file is not what the manifest renders. `pixi run airlock-check` runs it in the gates.
    - The facade routes `universe airlock render` to `universe-kit` — production — while `airlock exec`, `verify` and `restore` stay with `universe-airlock`, the consumer.

11. **`universe-kit watch [--package <name>] [--apply | --open-pr | --open-issue] [--dry-run] [--json]`**
    - Polls upstream providers (`github-releases`, `github-tags`, `pypi`, `crates-io`), compares normalized upstream versions against `recipes/<pkg>/recipe.yaml` (`rattler_conda_types::Version`), fetches new source archive `sha256` digests, and either opens/updates a deduplicated PR (`chore(deps): bump <pkg> to <ver>` with `build.number = 0`) or files/updates a single deduplicated upstream tracking issue.
