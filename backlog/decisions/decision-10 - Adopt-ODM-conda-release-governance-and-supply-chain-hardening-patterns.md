## Context

`Archont561/ODM-conda` is a sibling repository on the same pixi-sandbox / Backlog.md /
Lefthook / Convco toolchain lineage that packages pinned third-party C++ components with
rattler-build. A full review of its workflows, packaging scripts, recipes, skills, and
backlog (2026-10-27) identified governance and supply-chain controls that universe-kit
does not yet implement, even though both repositories publish to the
`archont561/archont561` channel and share decision-8's zero-checkout publishing principle.

The two repositories have different shapes: ODM-conda is a Python-orchestrated collection
of per-component recipes (linux-64 only), while universe-kit is a Rust product covering
six Conda subdirs. Only tooling-independent controls transfer; ODM's Python script layer and
multi-component registry are not copied.

## Decision

Adopt the following patterns, implemented in Rust and expressed as backlog tasks:

1. **Offline developer transport (`UNI-36`)** — choose a reproducible transport for the
   locked development environment. If a generated launcher is adopted, it must resolve its
   transport inputs from committed configuration, register user tools only through an
   explicit environment opt-in, and be covered by tests rather than hand-edited.
2. **Fail-closed release governance (`UNI-20`)** — a Rust release guard requiring exact
   tag/trusted-HEAD identity, a clean tree, repository-identity checks, and explicit human
   acknowledgement flags that default to `false`. The credentialed publisher performs no
   checkout and no repository-script execution; corresponding source is uploaded before the
   channel binary, and releases originate from published GitHub Releases rather than bare
   tag pushes. When implemented, this will bring the release workflow into alignment with the decision-8 target design.
3. **Artifact identity and payload-leak audit (`UNI-21`)** — filename/index metadata
   consistency, an explicit payload allowlist rejecting `.git`/`.pixi`/cache leaks,
   `$ORIGIN`-only RPATH enforcement, declared-dependency verification, and license-file
   presence checks, all reported through the `UNI-30` diagnostic and fragment contracts.
4. **Archive and source-fetch hardening (`UNI-22`)** — zip-slip/tar-bomb member validation
   with size and count caps, credential-free HTTPS with post-redirect scheme revalidation,
   mandatory cache re-hashing, download size caps, and a hermetic-source policy refusing
   submodules and CMake network-fetch tokens in enabled source trees.
5. **Installed-package tests and corresponding source (`UNI-23`)** — functional tests
   shipped inside the artifact and executed from a reinstalled prefix, deterministic
   allowlist-based source bundles with `SHA256SUMS`, installed `SOURCE.txt`, and license
   notices in both `share/licenses` and `info/licenses`.
6. **Auditable agent tooling (`UNI-28`)** — content-hash skill locks with offline CI
   verification, an explicit anchored Convco scope policy, `AGENTS.md` routing with a
   no-automatic-publish statement, and a contributor guide.

## Rejected / not adopted

- **Python packaging scripts and `recipes/components.json`** — ODM's per-component registry
  exists to coordinate many third-party recipes; universe-kit's equivalent source of
  truth is the `UNI-30` typed manifest schema (`universe.toml`/`package.toml`), and equivalent
  product logic belongs in the Rust crates, not repository Python.
- **The `agent-tools` Pixi environment split** — it works around a Bun ICU vs Python SQLite
  conflict that does not exist in this Rust/Python workspace.
- **linux-64-only scoping and snapshot-version conventions** — universe-kit targets all six
  supported subdirs and owns its own SemVer release track.

## Consequences

- Every adopted control is a separate reviewable task with its own acceptance criteria and
  test obligations; none weakens an existing gate, and acknowledgement flags ship `false`.
- The owner-lane release workflow gains an additional human gate before any upload, and the
  credentialed job's attack surface shrinks to artifact download, checksum verification, and
  the pinned upload client.
- Consumer universes generated by `universe-kit init` inherit the same guard and audit
  behavior through the Rust libraries, keeping owner and consumer lanes symmetric (decision-8).
- Backlog tasks `UNI-20`–`UNI-23`, `UNI-28`, and `UNI-36` implement this decision; the
  roadmap (doc-4) shows their placement across milestones M0, M2, and M4.
