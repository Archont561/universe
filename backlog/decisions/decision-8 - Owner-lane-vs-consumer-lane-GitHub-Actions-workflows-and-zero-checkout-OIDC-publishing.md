## Context

`universe-kit` requires two distinct workflow families:
1. **Owner-lane workflows** inside `Archont561/universe` (`ci.yml`, `autorelease.yml`, `release.yml`, `relock.yml`, `publish-sandbox.yml`) that test, version, build, and publish `universe-kit` itself onto `prefix.dev/archont561/archont561` and GitHub Releases.
2. **Consumer-lane workflows** rendered by `universe-kit init` into downstream universe repositories (`ci.yml`, `publish.yml`, `upstream-watch.yml`) that build, test, audit, and publish downstream Conda packages.

In both lanes, untrusted build execution (compiling upstream C++/Rust/Python sources or running package tests) must never execute in the same job context as OIDC publishing credentials (`id-token: write`) or API tokens, and owner releases must follow `Archont561` milestone-gated Convco conventions without burning SemVer versions on routine `main` merges.

## Decision

1. **Owner-lane workflows (`Archont561/universe/.github/workflows/`)**:
   - `ci.yml`: Runs on PRs and `main` pushes (`paths-ignore` for `backlog/**`, `docs/**`, `README.md`, while keeping `CHANGELOG.md` watched). Executes `gates` (`pixi run ci` + `pixi run test-e2e` + `skills-ref validate`) and `package` (`rattler-build build --recipe crates/universe-kit/recipe/recipe.yaml` + `universe-kit --help` smoke test) in parallel.
   - `autorelease.yml`: Implements the Convco-authoritative decision half:
     - On `push: branches: [main]`: runs in **observe** mode (`convco version --bump`), reporting the next calculated version in `$GITHUB_STEP_SUMMARY` without creating commits or tags.
     - On `push: tags: ['milestone-v*', 'm-v*']` or `workflow_dispatch`: runs full quality + packaging gates, computes/validates version via `convco`, updates `Cargo.toml`, `package.json` workspaces, `crates/universe-kit/recipe/recipe.yaml`, `skills/universe-kit/SKILL.md`, and `CHANGELOG.md`, verifies consistency via `pixi run repo-check`, pushes `chore(release): vX.Y.Z` + annotated tag `vX.Y.Z`, and dispatches `release.yml`.
   - `release.yml`: Triggered by `v*` tag push or `workflow_dispatch` (supporting `tag` + optional `existing_run_id` artifact reuse for failure recovery without rebuilding):
     - `verify`: runs `pixi run repo-check` so every manifest matches the tag.
     - `portal-bundle`: builds `@universe/portal` once on `ubuntu-latest` and uploads the deterministic static `packages/portal/build` artifact so non-Linux build runners (`win-64`, `osx-64`, `osx-arm64`) do not need Bun/Node during `rattler-build` compilation.
     - `build`: 4-platform matrix (`linux-64`, `win-64`, `osx-64`, `osx-arm64`) building `crates/universe-kit/recipe/recipe.yaml` with `rattler-build` and uploading `.conda` + standalone CLI archives.
     - `publish-prefix`: zero-source-build job running in `environment: prefix` (`permissions: { contents: read, id-token: write }`) invoking `rattler-build upload prefix -c archont561 "$pkg" --generate-attestation`.
     - `publish-github`: attaches `.conda` packages, standalone archives, and `SHA256SUMS` to the GitHub Release (`permissions: { contents: write }`).
   - `relock.yml` & `publish-sandbox.yml`: Standard `pixi-sandbox` lock refresh and GHCR sandbox pack publishing.
2. **Consumer-lane workflows (`universe-kit init`)**:
   - Generated workflows include a top-of-file header `# @generated by universe-kit <ver> — sha256:<digest>`; `universe-kit lint` detects drift and `universe-kit init --sync-workflows` upgrades them cleanly.
   - `publish.yml` enforces strict privilege separation:
     - `plan` (`contents: read`): runs `universe-kit plan --changed-or-missing --json` -> outputs `has_work` and `matrix`.
     - `build-and-audit` (`contents: read`, zero secrets, zero `id-token`): builds, runs isolated `rattler-build test`, runs `universe-kit audit --emit-fragment`, and uploads `.conda` + `.conda.json` artifacts.
     - `publish` (`contents: write`, `pages: write`, `id-token: write`, `environment: release`, **no untrusted repo code execution**): installs `universe-kit` directly from `prefix.dev/archont561/archont561`, downloads verified artifacts, publishes to `universe.toml` `[[targets]]`, updates the `universe-index` fragment store, runs `universe-kit pages build`, and deploys GitHub Pages via `actions/deploy-pages@v4`.

## Consequences

- Untrusted upstream tarballs compiled during recipe builds never have access to OIDC tokens, `GITHUB_TOKEN` write scopes, or channel credentials.
- Every release of `universe-kit` carries verified tag-manifest parity (`the Python repo check`), Sigstore attestations on `archont561/archont561`, and `existing_run_id` partial-failure recovery.
