## Description

The `v0.1.0` pre-release of `decision-132`, restated as one closed loop rather than a
list of capabilities. The owner's ask was concrete: Universe should be able to render
the release workflow, publish the declared Conda packages to branches, and hand a
consumer a rendered script that restores them — so that a developer can point a local
environment at that channel and work on Conda packages against it.

Four beats, in the order a consumer experiences them:

1. **Render.** `pixi run ci-render` writes the release workflow from this repository's
   own `universe.toml`. The file is committed and drift-checked, so the pipeline is a
   product of the manifest rather than a hand-written artifact that happens to work.
2. **Publish.** A tag run builds the three declared `linux-64` packages, audits them, and
   publishes their `.conda` bytes plus CEP-15/16 metadata to a Git branch and to
   prefix.dev. The branch is a static channel: metadata and bytes in one tree, at
   standard subdir paths.
3. **Restore.** The rendered entrypoint installs the published package on a host whose
   only reachable thing is Git. No hand-written script, no embedded digest — the digest
   is verified against the manifest inside the branch.
4. **Develop.** A `pixi.toml` naming the branch channel resolves `universe-airlock`
   into a fresh environment, which is what makes the channel usable as the foundation
   for developing Conda packages locally.

This milestone satisfies **no v1 surface** and does not reopen `decision-119`. It is a
checkpoint on the Conda track (`decision-132`), and `decision-119`'s six-surface gate
stands exactly as written.

## Tasks

Owned here, because they exist only for this checkpoint:

- `UNI-58` — publish the Conda channel to a Git branch, restorable with Git alone
  (`UNI-11`, `UNI-12` blockers). Its acceptance criteria carry the transport's shape:
  one orphan snapshot, whole files with a split only above the blob ceiling, budgets
  that refuse before the push, and a retention flag that says what it does and does not
  reclaim.
- `UNI-59` — cut the `v0.1.0` pre-release from the rendered workflow
  (`UNI-58`, `UNI-38`, `UNI-53`, `UNI-57` blockers).
- `UNI-74` — run a built package set in an environment sandbox (`UNI-52` blocker). This is
  beat 4 made a verb: a person who has just built a package installs the set into a prefix and
  runs a command inside it, instead of publishing first and finding out afterwards.
- `UNI-75` — host the channel index on GitHub Pages (`UNI-11`, `UNI-12` blockers). The published
  channel gets one address a solver can be configured with: the release renders the index from
  its own fragments and deploys it, and nothing generated is committed.

## Exit condition

All five are observable from outside the repository, and each one fails loudly:

1. `pixi run ci-render` writes the rendered set — `.github/workflows/universe.yml` for
   pull requests and pushes, `.github/workflows/release.yml` for tags — `pixi run
   ci-check` fails on any byte of drift, and every rendered file passes `actionlint`.
   (Corrected 2026-10-31: this read `universe-release.yml`, a name `decision-124`'s split by
   trigger family had already replaced.)
2. A run for the `v0.1.0` tag publishes all four declared packages' `linux-64` `.conda`
   files to all three destinations; the branch channel contains the bytes and the CEP-15
   repodata together and `pixi` resolves each package from it, prefix.dev resolves each by
   digest, and the GitHub Release carries the assets. (Corrected 2026-11-13: this read
   "three". `UNI-55` added the separately installable bootstrapper to the manifest, and the
   rebuilt channel that solved offline carried four.)
3. The rendered entrypoint, on a host with only Git and Pixi, installs the tagged package
   and `universe-airlock version` prints the version the tag claims.
4. A fresh `pixi` environment that names the branch channel installs `universe-airlock`
   without any other configuration — a developer can then build and audit packages
   locally against that same channel.
5. The same channel is readable at one address with no client and no credentials: the tag run
   renders the index from its own fragments and deploys it through GitHub Actions Pages, and
   the deployed `repodata.json` resolves the published packages by digest. Nothing generated
   is committed, so the site cannot describe a channel the release did not produce.
