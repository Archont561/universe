## Origin

GitHub issue #16, imported into Backlog on 2026-10-29. Unapproved design proposal.

## Proposal

Give every generated artifact (fragment envelopes, indexes, portal views, derived
payloads) a `# @generated by universe-kit <ver> — sha256:<digest>` header, and enforce
freshness with one declarative `generated_file_fresh` rule instead of per-artifact
hand-written drift checks.

## Reality check against this repository (verified 2026-10-29)

The issue's premise about today's state is **wrong in its specifics**, and the correction
matters because it changes where the work goes:

- `scripts/repo_check.py` contains no `@generated` handling — that part is right, and it
  never did. So there is nothing in `repo_check.py` to "replace", which is what AC#4 asks
  for. The workflow freshness check that does exist is `universe-kit ci check`
  (`crates/universe-kit/src/ci.rs` → `universe_workflow::check`, run as
  `pixi run ci-check`), and it is **stronger than a digest check**: it re-renders the
  workflow set from `universe.toml` and compares the bytes.
- ~~No workflow carries a generated header.~~ **Corrected 2026-11-08:** `.github/workflows/
  universe.yml` opens with `# @generated by universe 0.1.0 — manifest sha256:<digest>`,
  stamped by the template (`crates/universe-workflow/src/lib.rs`, `# @generated by universe
  {}`). The three owner-lane workflows (`ci.yml`, `relock.yml`, `publish-sandbox.yml`) are
  hand-written and unstamped, and no check would notice today.
- No generated fragments, indexes, or portal views exist yet; `universe-assets` embeds a
  placeholder bundle only, and the portal is scaffold-only. **Still true.**
- `scripts/skills_check.py` remains the closest working model for a content-hash gate, and
  the `ci check` render-and-compare remains the stronger one where the source is known.
- The issue's `# @generated` header cannot be added to JSON artifacts at all: a leading `#`
  line is not legal JSON. Whoever takes this has to choose between a sidecar digest file,
  a digest field inside the envelope, and a render-and-compare check.

## Prerequisites

- `UNI-10` for fragment envelopes and `UNI-46` for generated portal views.
- A header format decision that also covers files whose serialization must stay valid
  JSON/YAML (a leading `#` comment is not legal in JSON), which the issue does not address.
- The declarative-rule decision shared with draft-1 and draft-2.

## Recommended disposition

Keep as draft. If the stamping idea is adopted sooner, the smallest honest slice is
extending the existing `skills_check` hash model rather than inventing a second mechanism.
