## Origin

GitHub issue #16, imported into Backlog on 2026-10-29. Unapproved design proposal.

## Proposal

Give every generated artifact (fragment envelopes, indexes, portal views, derived
payloads) a `# @generated by universe-kit <ver> — sha256:<digest>` header, and enforce
freshness with one declarative `generated_file_fresh` rule instead of per-artifact
hand-written drift checks.

## Reality check against this repository (verified 2026-10-29)

The issue's premise about today's state is **wrong for this repository**:

- `scripts/repo_check.py` contains no `@generated` handling at all; there is no workflow
  drift check to "replace", because no workflow carries a generated header
  (`.github/workflows/` has `ci.yml`, `publish-sandbox.yml`, `relock.yml`, none stamped).
- No generated fragments, indexes, or portal views exist yet; `universe-assets` embeds a
  placeholder bundle only, and the portal is scaffold-only.
- What does exist is `scripts/skills_check.py`, which enforces content hashes against
  `skills-lock.json` — the nearest working model for a stamped-file freshness gate, and a
  better precedent than the workflow check the issue describes.

## Prerequisites

- `UNI-10` for fragment envelopes and `UNI-46` for generated portal views.
- A header format decision that also covers files whose serialization must stay valid
  JSON/YAML (a leading `#` comment is not legal in JSON), which the issue does not address.
- The declarative-rule decision shared with draft-1 and draft-2.

## Recommended disposition

Keep as draft. If the stamping idea is adopted sooner, the smallest honest slice is
extending the existing `skills_check` hash model rather than inventing a second mechanism.
