## Origin

GitHub issue #18, imported into Backlog on 2026-10-29. Unapproved design proposal.
Contains a cross-repository reference that must be removed before adoption (see below).

## Proposal

Record the current (package × capability) lint matrix behind a content fingerprint in a
committed `universe-lint-baseline.json`; make `lint check --baseline` fail only on
regressions, new packages, and new capabilities, with `--update` requiring an explicit
flag and an attribution record.

## Reality check against this repository (verified 2026-10-29)

- There is no curation matrix to baseline: zero packages are admitted, `universe-kit lint`
  does not exist, and no package × capability data is produced anywhere.
- `UNI-47` (offline test matrix and independent evidence review) already owns v1 evidence
  aggregation; a second matrix mechanism would need an explicit division of labour.
- The DoD asks that the baseline be regenerated by a "pixi-sandbox[bot] relock workflow".
  This repository's relock workflow (`.github/workflows/relock.yml`, decision-118) repairs
  lockfiles; it does not run product lint, so that step would be new work.
- The Notes section cites a "playtest parity baseline (separate issue on playtest)". House
  rule 9 forbids references to Universe-adjacent repositories; that reference must be
  dropped or restated in this repository's own terms before the proposal can be adopted.

## Prerequisites

- `UNI-7` lint surface and at least one admitted package (`UNI-10` output).
- A decision covering where the baseline file lives, how it is fingerprint-versioned, and
  how it interacts with `UNI-47` evidence.

## Recommended disposition

Keep as draft and strip the cross-repository reference. The forward-only idea is sound but
premature until a lint suite and a non-empty package set exist.
