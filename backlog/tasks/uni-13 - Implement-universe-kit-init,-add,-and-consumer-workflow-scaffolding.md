## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement consumer repository scaffolding and recipe onboarding (`universe-kit init` and `universe-kit add`, `doc-2`, `decision-1`, `decision-8`):
- `universe-kit init`:
  - Emits `universe.toml`, consumer `pixi.toml` (`channels = ["conda-forge", "https://prefix.dev/archont561/archont561"]` with explicit `channel = "https://prefix.dev/archont561/archont561"` pin on `universe-kit`), `.gitignore`, and the generated workflow files the manifest's declared capabilities call for. The set is derived and is one to four files (`decision-124`): `universe.yml` always; `universe-publish.yml` when stores are declared; `universe-airlock.yml` when lock adapters are declared; `universe-watch.yml` when upstream sources are declared. A consumer repository gets one file.
  - Stamps every generated workflow with `# @generated by universe-kit <ver> — sha256:<digest>` over the body only. The verbs are `universe ci render` (idempotent re-render, `--stdout` for inspection) and `universe ci check` (re-render and fail on any difference), not flags on `init` or `lint`.
  - Emits the setup step as exactly one line whose form is the only difference between owner and consumer mode (`decision-125`).
  - Enforces strict privilege separation in the generated publish file: unprivileged `plan`, `validate`, `build`, `audit` and `verify-artifact` jobs (`contents: read`, zero secrets/OIDC) followed by fan-out jobs that hold `id-token: write`, `packages: write`, or `contents: write` only where a destination needs them, each gated on the event. No job in `universe.yml` may require an `if:` on `github.event_name`; a job that needs one belongs in another file.
  - Verification is artifact-scoped: `verify-artifact` proves the built package installs and passes its declared smoke commands in a clean environment, and `verify-index` proves the published copy matches the built digest for the stores whose reads are anonymous, while a credentialed store is verified by the job that published it (`decision-128` §5).
The rendering engine itself — the `universe ci render` / `ci check` verbs, the embedded
templates, and the workflow this repository commits — lives in `UNI-57`; this task owns what a
generated repository contains and how it is derived. The split is recorded there.

- `universe-kit add <name> [--from-github | --from-pypi | --from-crates]`:
  - Queries upstream metadata, streams source tarball to compute `sha256`, detects SPDX license, and scaffolds `recipes/<name>/recipe.yaml` + `recipes/<name>/package.toml`.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `universe-kit init` emits exactly the workflow file set the manifest's declared capabilities call for — one file for a consumer repository, up to four for an owner (`decision-124`) — each stamped `# @generated by universe-kit <version> — sha256:<digest>` over the body, and every emitted variant passes `actionlint`.
- [ ] #2 Consumer `pixi.toml` places `conda-forge` first and pins `universe-kit` explicitly to `https://prefix.dev/archont561/archont561` (`decision-1`).
- [ ] #3 `universe-kit add --from-github` / `--from-pypi` / `--from-crates` scaffolds a recipe that immediately passes `universe-kit lint` (verified against `wiremock` fixtures).
- [ ] #4 The generated publish file keeps privilege separation: unprivileged `plan`, `validate`, `build`, `audit`, and `verify-artifact` jobs (`contents: read`, no secrets, no OIDC) precede fan-out jobs that hold only the privilege their destination needs, and no job in `universe.yml` carries an `if:` on `github.event_name`.
- [ ] #5 Verification is artifact-scoped: `verify-artifact` proves the built package installs and passes its declared smoke commands in a clean environment, and `verify-index` proves the published copy matches the built digest for anonymous-read stores, while a credentialed store is verified by the job that published it (`decision-128` §5).
