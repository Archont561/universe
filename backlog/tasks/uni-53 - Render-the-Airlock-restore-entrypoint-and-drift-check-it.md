## Description
<!-- SECTION:DESCRIPTION.BEGIN -->
Generate the committed entrypoint a disconnected host runs, from the manifest, and
verify that the committed copy still matches. `universe airlock render` writes the
POSIX and PowerShell entrypoints plus a short usage block for the project README;
`universe airlock render --check` re-renders and fails on any difference, so a
hand-edited script is caught in review rather than on the target host.

The entrypoint stays deliberately small: it detects the platform, fetches the
bootstrap manifest, verifies the runtime's digest, and then hands over to the
bootstrapper. Runtime digests are read from the manifest inside the branch, never
embedded in the script. Embedding them would rewrite every consumer's script on every
release of this tool; deferring to a manifest pins by commit instead and keeps the
generated bytes stable, which is what makes drift checking meaningful.

This is distinct from the bootstrap launcher described in UNI-33: that task owns the
verbs of the bootstrapper binary, while this one owns the generated text, its digest,
and its drift verification.
<!-- SECTION:DESCRIPTION.END -->

## Notes
<!-- SECTION:NOTES:BEGIN -->
2026-11-06 — the entrypoint renderer landed, and the two things it needed from the manifest are
new surface rather than invented defaults.

- **The pin is declared, not resolved.** `[airlock.developer.restore]` names `remote`, `branch`,
  `commit` and (optionally) `bootstrap`. A renderer that asked git for a branch head would
  produce a different file on every run, which would make the drift check noise, and a branch
  head would make the committed entrypoint fetch bytes it was not rendered against. The commit
  must be a full lowercase 40-hex id (`manifest.airlock.restore.commit`).
- **Values are validated, not escaped.** Every field is interpolated into a `sh` script and a
  PowerShell script, so the manifest holds them to a charset a single-quoted shell string
  survives — letters, digits, `. - _ ~ : / @ +` (`manifest.airlock.restore.unsafe`). Escaping at
  render time would be a second place to get it wrong, and a `remote` carrying `;` or `$(…)` is
  a manifest edit that changes what a consumer's host *does*.
- **The pin is checked rather than trusted.** The script checks out the commit and then compares
  `rev-parse HEAD` with it, so a force-pushed mirror branch fails at the consumer instead of
  running whatever now occupies that name. A ref published without an executable bootstrapper
  fails with a message naming the file.
- **Drift is a first-class verb.** `airlock render --check` exits `1` with an LCS line diff;
  `pixi run airlock-check` joins the `check` gate set. A scope deleted from the manifest leaves
  generated files behind, so they are drift too — `render` removes them, `--check` fails on
  them. For this repository the gate is currently vacuous by design: `universe.toml` declares
  no `[airlock]` scope, so it asserts only that nothing stale has been committed.
- **The facade exception.** `universe airlock render` reads `universe.toml` and writes committed
  files, so it routes to `universe-kit`; `airlock exec`, `verify` and `restore` stay with
  `universe-airlock`. The rendered workflow already called `airlock render`, so this also closes
  a job that pointed at a verb no binary implemented.
- **What is knowingly not here:** a *sealed* restore (no release key until `UNI-55`), a
  Pixi-managed environment (`UNI-51`), and the mirror lane that would publish the ref
  (`UNI-51`/`UNI-52`). The entrypoint's contract with the bootstrapper is fixed at
  `restore --commit <pin>`, which is the seam those tasks implement against.
2026-11-08 — the output location is configurable, and the split between the two places is
deliberate.

- **`[airlock.developer.restore] dir`** (default `.universe-airlock`) is where both entrypoints
  land. It lives in the manifest rather than only on the command line because the files are
  committed and drift-checked: `airlock-check` has to compare the files a reader will find, and
  a check whose path came from a flag nobody passed would report agreement with a manifest it no
  longer describes. The value must be relative, must not climb out of the project root, and
  holds the same conservative charset as the pin (`manifest.airlock.restore.dir`).
- **`--output <dir>`** overrides it for one invocation — a scratch render, a preview into a
  temporary directory. When the override differs from the manifest's `dir`, the render prints a
  warning on stderr naming what it left behind, because the committed entrypoint is then
  unchanged while `airlock-check` still compares it. Silent divergence is what would make the
  drift check untrustworthy; an override that agrees with the manifest says nothing.
- The README stays at `README.md`; only the scripts move. Its block is prose aimed at a reader
  of the repository's front page, and a per-project path for it would be a second location to
  keep in step for no gain.
