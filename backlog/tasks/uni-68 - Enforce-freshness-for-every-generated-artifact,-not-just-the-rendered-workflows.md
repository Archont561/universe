## Description
<!-- SECTION:DESCRIPTION.BEGIN -->
GitHub issue #16 asks for one freshness rule over every generated artifact. Its premise has
two errors worth keeping in view, because they change the work:

- It says `repo_check.py` verifies a `# @generated … sha256:<digest>` header. It never did.
  The check that exists is `universe-kit ci check` (`pixi run ci-check`), which re-renders
  the workflow set from `universe.toml` and compares bytes — stronger than a digest, since
  the source is the manifest rather than a hash of itself.
- It says no workflow carries a generated header. `.github/workflows/universe.yml` does:
  `# @generated by universe 0.1.0 — manifest sha256:<digest>`. The three owner-lane
  workflows (`ci.yml`, `relock.yml`, `publish-sandbox.yml`) are hand-written, unstamped,
  and unchecked.

The smallest honest slice is therefore not new machinery: it is extending the render-and-
compare check to the hand-written workflows, and deciding how a generated JSON artifact —
where a `#` comment is not legal — carries its generation.
<!-- SECTION:DESCRIPTION.END -->

## Acceptance Criteria
<!-- AC.BEGIN -->
- [ ] #1 A decision says how a generated artifact records its provenance: a sidecar digest, a field inside the envelope, or render-and-compare. JSON cannot take a leading `#` comment, so this is chosen rather than assumed.
- [ ] #2 The three owner-lane workflows are either rendered from a declared source or explicitly marked as hand-written outside the freshness check, so the set is exhaustive rather than accidental.
- [ ] #3 Every generated artifact that exists — rendered workflows today, fragment envelopes and portal views when `UNI-10` and `UNI-46` land — is covered by one check, and a stale one fails it.
- [ ] #4 The check reports the artifact path and what it was generated from, so a failure names the source to re-run rather than only the file.
- [ ] #5 No generated artifact is exempt without a recorded reason.
<!-- AC.END -->

## Definition of Done
<!-- DOD.BEGIN -->
- [ ] #1 The check is a Pixi task, in the gate that owns freshness, with a fixture that fails.
- [ ] #2 `pixi run gates` passes, and `pixi run ci-check` still catches a hand-edited rendered workflow.
- [ ] #3 The decision record is linked from the task and from the check's own documentation.
<!-- DOD.END -->
