## Description
<!-- SECTION:DESCRIPTION.BEGIN -->
GitHub issue #124 reports that `ci render --stdout` concatenates the rendered files with nothing
between them. Verified on `40bcf1ff`: `write()` maps each file's content into one string and
returns it, so with the common two-file set the second YAML document begins on the line after
the first document's last line.

The stdout contract is not the problem and does not change: stdout carries data, diagnostics carry
the rest (`decision-17`). What is missing is a boundary inside the data. A reader splitting the
stream has to recognise the `# @generated by universe` marker and cut there — guessing at a
format rather than reading one, and a guess that breaks the first time a document contains that
string.

The smallest honest fix is the one YAML already defines for this: `---` between documents. It
keeps the output a single valid YAML stream, keeps any document's own content byte-identical, and
leaves a split on that separator reproducing exactly the files the renderer produced — a property
a test can assert without recomputing the render.
<!-- SECTION:DESCRIPTION.END -->

## Acceptance Criteria
<!-- AC.BEGIN -->
- [ ] #1 Documents written by `--stdout` are separated by `---`, so the stream parses as one YAML document sequence.
- [ ] #2 Splitting the output on the separator reproduces each rendered file's bytes exactly and in the renderer's order, asserted against the same `RenderOutput` the files' own round-trip uses.
- [ ] #3 A single-file render is unchanged: no separator is invented where there is nothing to separate.
- [ ] #4 `--check`, the plain render path, and the `--json` envelope are untouched; the exit-code contract (0 matched, 1 drifted, 2 usage) is asserted as before.
